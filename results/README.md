# Reproducing the QA experiments

## Code version

Run the experiments from the submission branch, `exp/span-conditioned-confidence`.
Ensure it contains all source files and batch scripts referenced below.

| Experiment                  | Branch or tag                                        |
| --------------------------- | ---------------------------------------------------- |
| Baseline                    | `baseline-v1`                                        |
| Frozen reranking            | tag `final-frozen-v1`                                |
| Span-head reranking         | `span-head`                                          |
| Edge-aware reranking        | `exp/start-end-readouts`, tag `final-edge-frozen-v1` |
| Span-conditioned confidence | `exp/span-conditioned-confidence`                    |

## Environment

Run commands from the repository root on the SoC cluster.

- Python: `3.12`
- Install packages: `pip install -r requirements.txt`
- Set the source path: `export PYTHONPATH=src`
- Create the Slurm log directory before submitting jobs: `mkdir -p logs/slurm`

The commands below use `~/miniconda3/envs/qa/bin/python` for Python steps on the cluster.

## Required inputs

- Course data: `data/raw/train-v1.1.json` and `data/raw/dev-v1.1.json`
- Baseline checkpoint: `runs/baseline/model`
- Held-out validation files: `runs/baseline/validation-v1.1.json` and the reference predictions used by the held-out export job
- Split definitions: `splits/heldout-v1.json` and `splits/confidence-comparison-v1.json`
- Model and data settings: `configs/`
- Official scorer: `vendor/evaluate-v2.0.py`

Candidate exports and feature tables are generated under exports/ and are not committed.
Frozen weights and settings required to reproduce the reported final evaluations are tracked where noted.

## Run the experiments

### 1. Train the baseline

```bash
sbatch job_baseline.sbatch
```

This produces the checkpoint at `runs/baseline/model`.
Confirm that the job also creates the held-out validation files required by `job_export_heldout.sbatch`.

### 2. Prepare held-out inputs for reranking

Export the held-out candidates:

```bash
sbatch job_export_heldout.sbatch
```

Build the candidate table:

```bash
PYTHONPATH=src ~/miniconda3/envs/qa/bin/python -u \
  -m qa_baseline.candidate_table \
  --exports exports/v1/heldout \
  --split splits/heldout-v1.json \
  --output exports/v1/heldout/table.npz
```

Build text features:

```bash
PYTHONPATH=src ~/miniconda3/envs/qa/bin/python -u \
  -m qa_baseline.text_features \
  --exports exports/v1/heldout \
  --validation runs/baseline/validation-v1.1.json \
  --output exports/v1/heldout/text_features.npz
```

### 3. Run the frozen reranker comparison

Run article-level cross-validation and freeze the selected settings:

```bash
sbatch job_cv_all_features.sbatch
sbatch job_freeze.sbatch
```

Record the frozen settings before evaluating on dev. Then prepare dev:

```bash
sbatch job_export_dev.sbatch

PYTHONPATH=src ~/miniconda3/envs/qa/bin/python -u \
  -m qa_baseline.dev_table \
  --exports exports/v1/dev \
  --dev data/raw/dev-v1.1.json
```

Score dev:

```bash
sbatch job_dev_score.sbatch
```

### 4. Run the span-head reranker

This workflow uses the held-out and dev exports prepared above.

```bash
sbatch job_span_head.sbatch
sbatch job_fit_final_head.sbatch
sbatch job_evaluate_dev_head.sbatch
```

See the Python module docstrings for direct commands and arguments.

### 5. Run the edge-aware reranker

Export and prepare held-out edge features, run cross-validation, then fit and record the final head before scoring dev:

```bash
sbatch job_export_edges_heldout.sbatch
sbatch job_prepare_edges.sbatch
sbatch job_cv_start_end_l2wide.sbatch
sbatch job_fit_final_edges.sbatch
```

After freezing and recording the settings, export and prepare dev, then score it:

```bash
sbatch job_export_dev_edges.sbatch
sbatch job_dev_table_edges.sbatch
sbatch job_dev_score_edges.sbatch
```

### 6. Run the span-conditioned confidence head

#### Build the shared confidence examples

The confidence head uses the shared held-out split: 5,845 `head_train` questions and 2,896 `calib` questions from `splits/confidence-comparison-v1.json`.

The required examples file is `exports/v1/heldout_edges/confidence_examples.npz`. It was generated by a shared preparation workflow on another branch.

Fit the confidence head:

```bash
sbatch job_fit_span_confidence.sbatch
```

The scoring job requires the dev edge export at `exports/v1/dev_edges`. If it has not already been prepared by step 5, run:

```bash
sbatch job_export_dev_edges.sbatch
```

Then score dev:

```bash
sbatch job_score_span_confidence.sbatch
```

Expected outputs include `exports/v1/final_confidence/span_confidence_head.npz`,
`exports/v1/final_confidence/span_confidence_summary.json`, and the dev summary and predictions under `exports/v1/final_confidence/dev/`.

## Results and scoring

### Frozen reranker’s scorer check

See `results/` for the reported metrics and settings. To recheck the frozen reranker’s dev predictions with the project wrapper for the official SQuAD scorer:

```bash
PYTHONPATH=src ~/miniconda3/envs/qa/bin/python -u \
  -m qa_baseline.evaluate \
  --data data/raw/dev-v1.1.json \
  --predictions exports/v1/final/dev/predictions-frozen-head-plus-mix.json \
  --output exports/v1/final/dev/metrics-frozen-head-plus-mix.json
```

The confidence head changes confidence scores, not answer selection; evaluate it with its confidence metrics rather than interpreting it as a reranker.
